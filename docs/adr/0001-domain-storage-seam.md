# Единый доменный шов хранения с адаптерами Supabase, LocalStorage и In-Memory

Хранилища Pinia (`transactionStore`, `categoryStore` и `reportStore`) обращаются к данным исключительно через единый порт `BudgetStorage` (`src/core/storage/`), а не вызывают клиент Supabase, IndexedDB или построители запросов PostgREST напрямую. Для работы с облаком предусмотрен адаптер `SupabaseStorage` с ленивой инициализацией, для автономного локального хранения на устройстве — персистентный адаптер `LocalStorage` (`createLocalStorage()` на базе IndexedDB с fallback в `window.localStorage`, хранением метаданных синхронизации `updatedAt`/`deletedAt`, генерацией `UUID` и стартовым набором категорий `DEFAULT_CATEGORIES`), а в тестах через `setStorage()` подставляется адаптер `InMemoryStorage`. Это предотвращает утечку сгенерированных типов схемы БД (`database.types.ts`), деталей IndexedDB и `PostgrestError` в сторы и компоненты, а также позволяет быстро и детерминированно тестировать публичный интерфейс сторов и безопасно переключать среду хранения (Local-First / Cloud).
