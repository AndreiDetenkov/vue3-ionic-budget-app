# Единый доменный шов хранения с адаптерами LocalStorage, Firebase Delta-Sync и In-Memory

Хранилища Pinia (`transactionStore`, `categoryStore` и `reportStore`) обращаются к данным исключительно через единый порт `BudgetStorage` (`src/core/storage/`), а не вызывают IndexedDB или внешние SDK напрямую. По умолчанию в приложении используется персистентный локальный адаптер `LocalStorage` (`createLocalStorage()` на базе IndexedDB с fallback в `window.localStorage`, хранением метаданных синхронизации `updatedAt`/`deletedAt`, генерацией `UUID` и стартовым набором категорий `DEFAULT_CATEGORIES`), а для переноса данных и резервного копирования в `src/core/storage/backup.ts` реализованы экспорт/импорт JSON-бэкапов с Last-Write-Wins слиянием (`mergeSnapshots`).

Для облачной синхронизации между устройствами базовый локальный адаптер оборачивается в `createSyncedLocalStorage()` с сервисом инкрементального `Delta-Sync` `createFirebaseSyncService()` (`src/core/storage/firebaseSync.ts`), который выполняет батч-запись до `MAX_FIRESTORE_BATCH_SIZE` (450 операций), отслеживает синхронизированные версии на уровне записей и сдвигает `lastPulledAt` только по удалённым дельтам без эхо-перезаписи. Клиентский контроллер `createFirebaseCloudController()` (`src/core/storage/firebaseClient.ts`) лениво инициализирует Firebase Auth (Google Sign-In через `signInWithPopup` с fallback на `signInWithRedirect` и опциональной клиентской проверкой `VITE_FIREBASE_ALLOWED_EMAILS`) и Firestore-адаптер `createFirestoreRemoteAdapter()` под строгие правила `firestore.rules` и доступен через `useFirebaseCloud()`. В тестах через `setStorage()` и `setFirebaseCloud()` подставляются изолированные адаптеры (`InMemoryStorage`, тестовый `LocalStorage` или мок контроллера облака). Это полностью изолирует сторы и компоненты от деталей хранения и позволяет быстро и детерминированно тестировать публичный интерфейс приложения.
