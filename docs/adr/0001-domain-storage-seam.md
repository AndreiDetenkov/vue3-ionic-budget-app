# Единый доменный шов хранения с адаптерами Supabase, LocalStorage и In-Memory

Хранилища Pinia (`transactionStore`, `categoryStore` и `reportStore`) обращаются к данным исключительно через единый порт `BudgetStorage` (`src/core/storage/`), а не вызывают клиент Supabase, IndexedDB или построители запросов PostgREST напрямую. По умолчанию в приложении используется локальное хранилище `createAutoMigratingLocalStorage()` поверх персистентного адаптера `LocalStorage` (`createLocalStorage()` на базе IndexedDB с fallback в `window.localStorage`, хранением метаданных синхронизации `updatedAt`/`deletedAt`, генерацией `UUID`, стартовым набором категорий `DEFAULT_CATEGORIES` и одноразовой авто-миграцией из Supabase при пустой локальной базе). Для чтения данных из облака при миграции и ручном импорте (`src/core/storage/backup.ts`) используется адаптер `SupabaseStorage` с ленивой инициализацией, а в тестах через `setStorage()` подставляется `InMemoryStorage` или тестовый `LocalStorage`. Это предотвращает утечку сгенерированных типов схемы БД (`database.types.ts`), деталей IndexedDB и `PostgrestError` в сторы и компоненты, а также позволяет быстро и детерминированно тестировать публичный интерфейс сторов и безопасно переключать среду хранения (Local-First / Cloud).
